# Agent 宿主兼容范围

四个宿主均可使用统一 MCP 模型任务协议。当前主要实测环境为 Windows；下表列出实际走过的路径，安装者仍需配置自己的模型和平台账号。

| 宿主 | 当前会话模型路径 | 后台执行 | 真实验证范围 |
| --- | --- | --- | --- |
| DSH | 支持 | 使用配置的 DSH CLI | 原生 MCP 模型调用；统一队列与后台 CLI 使用归档字幕隔离回放，生成真实判断 |
| WorkBuddy | 支持 | 暂不提供已验证后台入口 | 真实采集、当前会话提交新判断、生成草稿；已有冻结草稿跨宿主邮箱投递验证 |
| TRAE | 支持 | 可配置 CLI，发行版需另验 | 真实采集、原生 MCP 当前会话提交新判断；无精选时正常结束 |
| Codex | 支持 | 可配置 CLI，后台模型响应需另验 | 项目范围原生 MCP，真实采集，当前会话提交 3 条新判断并生成草稿 |

这组结果证明上述环境中的实际路径可运行；不同桌面发行版、模型渠道、邮箱连接和长期后台运行需分别确认。当前会话模型与后台 CLI 是两条路径，桌面会话成功不等于后台授权已配置。

## 日常运行

在验证台创建计划并选择实际使用的宿主，首次保持“仅生成草稿”。按 [统一任务指南](AUTOMATION.md)让当前 Agent 调用 `radar_automation_next`、`radar_automation_start`，阅读返回任务，再 `radar_automation_submit`。该路径使用当前会话模型。

旧单平台入口 `radar_bilibili_interest_round` 使用本机配置的分析执行器；需要明确使用当前宿主模型时，选择统一任务入口。计划选定宿主与实际会话应一致。

## 服务与连接更新

`radar_status.service` 描述当前 MCP 进程；`operator` 描述统一调度服务。需要 `service.restartRequired=false`、`operator.ready=true` 才开始统一轮次。

升级后，本地调度服务和 Agent 的 MCP 连接都需要加载新代码。网页服务已更新而旧会话仍报告旧版本时，应重连该宿主的 MCP；必要时保存其他工作后重启宿主。不要反复启动第二个调度器。

## 阅读与投递边界

- 当前 B站自动计划读取 P1 字幕，缺字幕时可使用已配置的本地语音回退；按实际提供字符范围记录，截断材料不能声称全文已读。
- 无可读正文、采集或判断失败、模型判断不选中分别报告；没有任务就没有新的模型阅读判断。
- 模型任务和阅读轨迹记录调用方提交的信息，不作为底层模型身份或逐字理解的独立证明。
- 生成草稿不等于发信。当前宿主有自己的邮箱连接时才可按授权领取并发送；后台执行使用 SMTP，需安装者另行配置。
- 定时执行需要电脑和服务持续运行；当前会话模式还需 Agent 持续领取任务。服务不能唤醒已经关闭的宿主。

# 从视频与仓库资料整理开发灵感

在侧边目录打开“开发灵感”，选择自己的B站主题、执行Agent和视频—仓库关联，点击“准备Agent指令”，复制到当前Agent。生成完成后刷新卡片，可导出Markdown。

关联来自当前主题实际提供范围内的视频正文或简介中的明确GitHub链接。不从标题、弹幕、相似名字或已被替换的历史材料猜仓库。没有明确链接时，先正常阅读更多视频。

## 当前Agent的流程

1. `radar_inspiration_list(topicId)`查看有界候选和已有卡片。
2. `radar_inspiration_prepare(topicId, videoKey, repo, agent)`取得任务；若返回`REPO_BODY_REQUIRED`，用已有`radar_github_read`补读这个明确引用的公开仓库，然后再准备。缺视频正文则先解决视频阅读，不能只靠简介生成卡片。
3. `reused=true`表示同主题版本和两来源快照已有卡片，保留原作者，不冒充当前模型重新阅读。否则当前会话模型阅读返回的`prompt`，按`schema`生成结果，并调用`radar_inspiration_submit(jobId, token, result)`。
4. 需要停止时调用`radar_inspiration_cancel(jobId, token)`。租约10分钟，同一快照不能并发重复生成；无效结果可在原有效租约内纠正。过期、取消或来源/主题变化后停止旧提交。

四个宿主共用此流程。宿主名是调用方声明，引用表示模型报告，不能独立证明语义理解或身份。prepare只读取本地归档；不会隐式启动后台模型、联网或发送邮件。

## 卡片记录什么

- **材料中的机制**：每项引用本任务局部材料编号；整体必须包含视频正文和仓库README/源码的引用。
- **最小开发建议**：目标、步骤、依赖和验证办法，明确属于尚未执行的建议。
- **来源与范围**：两来源快照、提供字符数、截断、文本分段及限制。

每次给模型提供视频和仓库各最多20000字符。视频仍遵守主题标准P1/5000或扩展前三P/每份15000的范围；达到预算后不继续补入。仓库使用已取得的README、源码或Release文本，至少要有足够README/源码正文。简介、元数据或许可证不能替代正文。

网页按主题扫描最近最多100条视频，最多200个关联，每视频最多5个明确仓库；全主题工具列表最多20个主题。卡片按主题显示最近50张。达到上限时保留“可能还有”提示，可按主题缩小查询。旧卡在材料或主题变化后标为历史，保留导出，不改写原始资料。

卡片保存在本地SQLite的独立jobs命名空间，纳入原数据库备份。它不是新的邮件模板或发送授权；本版不自动对每轮视频跟进生成卡片，不执行仓库代码，也不改变定时任务。需要时由所选Agent按上述指令生成，现有简洁邮件继续独立使用。

如果两来源材料无法支持与用户目标有关的方案，模型可以提交proposal=null并说明原因；保留这次阅读记录，不强行生成步骤，同快照仍可复用。

# 内容与互动变化记录

在已有“分析已归档内容”区域输入条目ID，点击“读取已有判断”，展开“变化记录”。同一信息也随radar_archive_analysis返回，无需新增工具。显示最近30条，本地早期没有记录的计数不追溯猜测。

- 首次取得：建立本地观察基线。
- 版本变化：取得的版本字段不同。
- 正文或材料变化：既有内容指纹不同；它表示需重新核对的材料差异，不等于已证明有新的推荐价值。
- 互动数变化：两次取得的已知非负整数不同，记录前后值；不会改变正文指纹、阅读快照或已推荐去重。

GitHub使用原元数据请求中的stargazers_count、forks_count、watchers_count；watchers_count按REST原字段记录，不当作独立订阅人数。B站使用原视频信息中的播放、点赞、投币、收藏、分享、弹幕数和评论数，只取计数，不读取评论正文。接口未返回、非整数或无效值视为未知；首次取得或未知转已知不称为数量变化，未知不填零。后续变少同样按原值记录。

互动数只写档案，未增加平台请求、模型调用或投递。内容或版本变化后仍需经过主题、正文与模型判断及既有投递策略，不保证再次推荐。按平台稳定ID去重，不进行语义强制合并，也不会更改已有冻结邮件。

记录保存在现有events及logs表，属于本机数据库备份；不改变数据库结构或默认配置。旧档案无需迁移，早期事件没有前后计数则保持未知。历史查询有界，不保证完整平台历史或实质变化的语义识别。

## 弹幕观察与内容指纹（beta.24）

B站的danmaku及danmaku:pN材料属于观众反应，不计入视频正文指纹。两次都取得样本且不同，单独记录“弹幕样本变化”；没请求、失败或缺失不当作空样本。已取得的明确空样本可以参与比较。字幕、标题、版本及其他材料继续按原规则判断，不扩大为智能识别所有无价值变化。

所有实际材料ID仍进入阅读快照，因此弹幕更新可能使旧判断标为历史。这与推荐去重分开：重新阅读后仍不因仅弹幕不同而重复推送同一正文。旧版指纹仅在完整旧当前证据可验证正文等价时沿用，不改写历史邮件或批量迁移数据库；旧材料缺失时不能猜等价。

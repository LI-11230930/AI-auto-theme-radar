# 主题雷达 · Theme Radar

让 Agent 按你的兴趣阅读 B站视频和 GitHub 项目，筛选后生成简洁中文邮件。

**v0.1.0-beta.33** · 本地优先 · Node 24 · SQLite · MCP · MIT

```text
兴趣主题 → 推荐/搜索 → 字幕或语音转写 → Agent筛选 → 中文摘要与流程示意 → 邮件草稿
                              ↓
                     可检索档案 · 去重 · 阅读记录
```

## beta.33：历史记录不影响防重复保护

平台触发从完整账本判断运行中与同版本待投递草稿，避免最近30条展示截断造成漏判。平台触发在租约写事务内再核对独占与待投递条件，两个进程同时触发也只领取一轮；展示数量和普通手动计划契约保持原样，不重发旧邮件。

## beta.32：备份恢复核对约束结构

备份检查同时核对字段、主键、唯一约束、外键、排序规则及表模式，避免仅列名相同就误报可恢复。普通非唯一索引和等价改名唯一索引保持兼容；检查或演练均不迁移源文件、不替换当前账本。备份范围仍是SQLite，配置与媒体文件另行保管。

## beta.31：回执重复确认，不重复发送

统一邮件回执已经保存但响应丢失时，再次报告完全相同的结果会返回duplicate=true，保留原记录。不同消息ID、状态逆转和独立核查结果均不能覆盖；领取发送仍只有一次，未知结果不重发，相同报告不等于邮件已送达。

## beta.30：取消与超时结束任务进程

POSIX环境中，Runner先终止自己的独立进程组，1秒后仍未关闭则强制终止；父进程先退出但后代仍持有输出管道时也会清理。Windows继续使用已有进程树终止路径。统一轮次的取消、关闭和修改计划沿用同一退出链路，保留取消记录。

## beta.29：关闭执行器后停止新增工作

修复关闭后仍可能领取、建立或提交模型任务及预留发送尝试的问题。长轮询等待期间关闭也会以CANCELLED停止；不接管其他会话任务。已发起邮件仍可登记submitted/uncertain结果，结果未知不会因此重发。

## beta.28：从邮件回到本机调整偏好

“邮件内容”中可开启精选反馈入口。主题项目与视频后显示“有用 / 不感兴趣”，点击只预填原条目、主题和意向；填写偏好词后先预览，再明确应用，可撤销。公共默认关闭，旧冻结邮件不变。日周榜没有主题判断的条目不猜测绑定；本机链接需要同一台电脑的服务运行，手机或其他电脑不能连接原电脑的localhost。详见[邮件反馈](docs/MAIL_FEEDBACK.md)。

同时修复统一队列中已被其他会话领取、已完成或父轮次失效的队首阻止后续任务的问题；会话独占和过期保护保留。

## beta.27：新日志按字段过滤凭据

修复password、嵌套access_token等字段原样写入日志的问题，扩展认证头、已知GitHub令牌、代理用户信息及私钥块过滤。普通错误码、条目ID与计数保留。只影响新的日志写入，不修改历史记录；日志仍需人工核对后分享，不能把它当作已脱敏的内容导出。

## beta.26：读取能力与凭据状态保持一致

修复显式GitHub凭据不可用时，能力栏仍显示公开读取可用的问题。凭据受阻或尚未加载时明确显示阻止，并保留限流冷却信息；匿名与已配置状态均不代表本次联网已验证。凭据加载、网络和邮件策略保持原样。

## beta.25：准确区分实际读到的文字

修复能力摘要把画面OCR计入字幕的问题。字幕、语音转写、采样画面OCR分别计数；当前模型引用还需有实际提供字符范围。同一视频可属于多类，判断份数与视频数分别展示。原配置和执行流程保持，现有阅读预算见[阅读与降级边界](docs/READING_BOUNDS.md)。

## beta.24：弹幕样本更新不重复推送视频

修复同一视频正文未变、仅弹幕样本刷新就被当作正文更新的问题。弹幕样本单独记录变化，保持已推荐去重；阅读快照仍随实际材料更新，旧判断不会冒充当前阅读。兼容已有指纹和冻结投递，无需迁移配置。

## beta.23：区分内容更新与互动增长

档案分析现在保留版本、正文/材料与互动计数的独立变化记录。仅Star或视频互动数变化时，不重新推荐已推内容；缺失计数不补零，首次取得建立基线。记录来自已请求的公开元数据，不增加评论读取、模型或发送。详见[变化记录](docs/CHANGES.md)。

## beta.22：可选地跟进精选视频

首页勾选“从B站精选整理开发灵感”后，统一轮次会沿用当前Agent，对本轮精选正文中明确引用的仓库补读并整理卡片。默认每轮最多1张卡、补读1个仓库；高级计划可分别设为1–3张与0–3次补读。额外跟进最多3分钟，同轮相同仓库只处理一次，失败仍保留正常汇总邮件。旧计划默认关闭，卡片在独立目录查看，不塞进邮件正文。

## 从视频与仓库走到开发灵感

侧边目录新增“开发灵感”：选择主题、Agent和视频明确引用的仓库，把指令交给当前Agent。它阅读两来源正文后，分别整理材料机制与最小开发建议，附步骤、依赖和验证办法；可导出Markdown，来源变化后旧卡标为历史。

不凭视频标题猜仓库，缺正文时先补读；不会自动执行代码或改变邮件与定时。四宿主共用租约和提交协议，当前Agent实际阅读，单快照可复用。操作与范围见[灵感卡指南](docs/INSPIRATION.md)。

## 可选多分P与长字幕分段

在“兴趣主题”的“B站阅读深度”选择标准或扩展。标准保持P1、每份正文最多5000字符；扩展取得实际存在的前三P，每份视频正文最多15000字符，按连续5000字符片段交给同一个Agent任务。单任务材料总预算仍为50000字符，超出部分在档案中标明截断。

旧主题不会自动升级阅读深度。P1缓存不能代替前三P；P2/P3有正文时可以参与筛选。语音和画面回退仍仅用于P1，不为其他分P下载媒体；文本分段不代表完整观看或增加音频处理时长。

## 按开发目标阅读，用反馈调整偏好

在“兴趣主题”写下想开发的工具或插件，设置搜索关键词和可选的优先偏好。填写开发目标后，可选择优先有具体机制、接口、代码或可复现步骤的内容；旧主题继续按原描述工作，不要求重新配置。

“有用”反馈可以先预览为优先短语，明确应用后才调整这个主题的候选阅读顺序和模型相关性；“减少此类／不相关”继续预览排除词。规则可撤销，存在后续修改时会拒绝覆盖。偏好不会扩大搜索、替代正文或保证入选，重复线索也不会自动合并内容。操作见[自定义说明](docs/CUSTOMIZATION.md)。

Windows加密组件冷启动可等待最多30秒，并区分超时与凭据无法解密；服务启动等待也与之衔接，避免忙碌环境误报需要重新输入令牌。

## 统一配置与真实运行状态

首页保存一次Agent、主题、邮箱及发送选择，会原子同步已经创建的GitHub/B站平台计划。保留各自开关、频率、标题与额度；取消选择的平台会停用，已关闭的平台不会因保存而开启。不修改其他自定义计划。原主题、材料和已发送邮件保留。

平台卡片分别显示计划开关、目标时刻、实际唤醒配置、Agent与收件人。暂停或未配置唤醒时不会显示为自动执行就绪；填写邮箱不代表宿主已连接。自动任务建议放在独立的专用运行会话，开发聊天不承担日常轮询。

GitHub可使用GITHUB_TOKEN环境变量，Windows也可用加密保存工具：`theme-radar-app/tools/set-github-token.ps1`。MCP、CLI和服务使用同一加载逻辑；已更新的保存记录会提示重启加载，不要求重复输入。详见[统一任务指南](docs/AUTOMATION.md)。

## 统一运行与自定义频率

首页提供侧边目录和简洁配置：选择主题、平台、Agent和邮箱，保存后把运行指令交给所选Agent。它会自主采集、阅读、筛选并通过已连接的Outlook投递；可以只在需要时手动运行，无需设置时间。详细材料、原始模板和调度工具保留在高级区域。

beta.6在验证台新增统一计划：选择自己的主题、B站/GitHub平台、Agent、每日时刻/星期或分钟间隔，再选择仅草稿、SMTP或当前Agent邮箱。四宿主共用同一执行协议：交互模式使用当前宿主模型，后台模式使用明确配置的CLI，不隐式改用DSH。

首次保持仅草稿。验证通过后，使用者自行开启计划及发送授权；旧配置、旧手动政策和发送暂停不会自动迁移。电脑与本地服务需持续运行；交互模式还需Agent会话持续参与，无法自动唤醒关闭的应用。WorkBuddy目前只支持交互模式。完整步骤见[统一任务指南](docs/AUTOMATION.md)。

beta.7增加已完成草稿的单封交接：查看冻结正文与完整预览地址，明确批准本封后，交给已连接邮箱的Agent发送一次。分析宿主和发送宿主可以不同；原计划可以继续暂停。

## 可以做什么

- **B站兴趣阅读**：登录后使用推荐和主题搜索，每轮最多20个候选、读取3条视频；按主题选择P1或实际前三P；不限于固定UP主。字幕优先，可选本地 faster-whisper 语音回退。弹幕只作辅助材料，不读取评论。
- **作者订阅**：按UID区分作者；公共投稿接口受限时，可用扩展把当前可见链接直接交给验证台，再逐条核对真实UID和正文。
- **GitHub主题汇总**：用户自选主题，读取公开仓库资料；生成主题精选、Trending Daily前十和Weekly前十，附中文介绍、对应周期新增Star、累计Star与简短流程示意。Trending是GitHub公开展示顺序，不是全站项目新增Star的独立排名。
- **邮件与档案**：正文保持简洁，详细引用与阅读范围留在本地档案；支持检索、变化检测、反馈规则和跨来源归并。发信默认关闭，需要自己的SMTP或Agent邮箱连接。
- **本机数据库备份**：网页创建快照并执行隔离恢复演练，检查15张表、旧租约和发送中断记录；不覆盖正式账本或重发邮件。配置、登录和冻结样张文件需另行保留。
- **多宿主接入**：提供DSH、WorkBuddy、TRAE和Codex的MCP配置片段，共用同一份本地SQLite数据。当前主要验证环境为Windows；统一计划支持当前会话模型或明确选择的后台CLI。

## 启动仅需五分钟

安装 **Node 24.14以上的24.x**，下载源码后在仓库根目录运行：

```sh
node theme-radar-app/tools/bootstrap.ts
```

也可以使用 `npm start`。不需要先执行 `npm install`；基础功能没有外部npm运行依赖。命令首次创建空主题配置、生成MCP配置片段并启动验证台，重复启动保留配置。

打开 **http://127.0.0.1:8767/** ：

顶部“开始使用 · 配置检查”列出各阅读入口的准备情况和下一步。也可运行 `npm run doctor`；本机检查不消耗模型用量，不请求平台或邮箱。

主题数量由你决定。状态面板根据当前有效判断、模板和发送通道显示，不继承开发者个人验收结论。“生成本地档案预览”使用已归档材料及你的邮件模板，不调用平台、模型或邮箱。

1. 在“B站连接”用自己的B站App扫码；连接只保存在本机。
2. 先在主题设置创建自己的主题，选择平台、关键词和排除词；作者订阅填写自己的UP主UID。
3. 按[安装说明](theme-radar-app/INSTALL.md)连接已有DSH模型渠道，或把生成的MCP片段导入自己的Agent。
4. 在“B站兴趣自主阅读”开始一轮，查看取得的正文、模型判断和草稿。

仅启动网页不等于配置好了模型。未配置模型时会返回明确错误；可以先运行离线演示：

```sh
node theme-radar-app/src/cli.ts demo
```

## 交给 Agent 的任务

先创建主题及统一计划；以下 `my-plan` 和 `Codex` 需替换成自己的计划ID和实际宿主。接入MCP后可使用：

> 用主题雷达运行一轮my-plan计划，当前宿主为Codex。先检查radar_status确认服务就绪，再调用radar_automation_next(agent="Codex")和radar_automation_start(planId="my-plan")。循环next，用你当前会话模型阅读返回的task.prompt，按task.schema生成独立结果并submit；通过status查看本轮直到结束。报告新判断、复用、跳过原因和草稿完整预览地址。不修改计划，不开启第二轮；本次只生成草稿，不发信或启用定时。

四宿主配置及邮件交接见[工作流](theme-radar-app/integrations/WORKFLOW.md)，实测范围见[宿主兼容说明](docs/HOST_COMPATIBILITY.md)。模型授权与邮箱授权分别配置；本仓库不携带任何账号、模型密钥或邮箱连接。

## 自定义邮件

验证台的“自定义邮件内容与模板”可设置邮件标题、GitHub内容栏目与顺序、条目排版及页脚。可删去Star或流程占位符；B站标题、格式独立配置。收件人、SMTP和Agent邮箱连接由安装者设置，默认不发送。详见[自定义说明](docs/CUSTOMIZATION.md)。

## 邮件长什么样

GitHub邮件包含三部分：主题项目链接与简短中文介绍、Daily前十、Weekly前十。每项可附2至4节点的用途或运行示意；Star未知时保留未知。B站邮件包含视频链接/BV号、简短介绍和示意。示意图是材料概括，不表示执行过项目代码。

旧单平台网页和兴趣CLI只生成草稿；统一计划可在明确启用后编排投递。B站手动邮件由具有邮箱连接的Agent执行领取、发送、记录结果，默认每轮1次、每天2次、每封3条；失败或结果不明不自动重发。GitHub SMTP需要另行启用配置。参考[使用指南](docs/USAGE.md)。

## 首版边界

| 能力 | 当前情况 |
| --- | --- |
| B站字幕、缺字幕P1语音回退、兴趣筛选 | 已有真实阅读与用户验收；ASR需另装Python和模型 |
| 扩展作者清单直接交接 | 0.3.2，主动提交当前可见链接 |
| GitHub Daily / Weekly与简洁正文 | 已实现；网络限流和页面变化可能中止采集 |
| DSH / WorkBuddy / TRAE / Codex | 各有真实模型执行证据，Codex原生统一轮次已生成草稿；详细范围见宿主兼容说明 |
| 云端无人值守、超过前三P、完整画面理解、小红书 | 后续版本范围，不作为首版已完成能力 |

持续作者发现受平台接口限制；扩展只接收当前可见链接，不自动滚动全量投稿。阅读文字不等同于观看画面或核验视频中的新闻事实。[已知限制](docs/LIMITATIONS.md)列出首版范围。

## 开发与检查

```sh
npm test
node theme-radar-app/tools/check-installation.ts
python -m unittest discover -s theme-radar-app/tests -p smtp_bridge_test.py
```

测试使用临时数据库与模拟平台资料；不会调用真实模型或发送邮件。SMTP检查使用离线替身。CI覆盖Windows和Linux的自动化测试，不代表两个系统的真实账号全部验收。

目录：`theme-radar-app/`为程序与测试，`browser-extension/`为可选扩展，`docs/`为使用和发布说明。私有配置、Cookie、数据库、模型、邮件正文及开发过程档案不在发布目录中。
